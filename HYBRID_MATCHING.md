# Hybrid matching system

The primary workflow is one authenticated Young volunteer ranked against eligible elderly help requests. See [YOUNG_MATCHING.md](YOUNG_MATCHING.md) for architecture, privacy, 240-character explanations, provenance, compatibility and deployment.

The existing owner/coordinator volunteer-for-request endpoint is retained for compatibility and historical benchmark replay. It is not invoked by the elderly UI. Original benchmark reports describe that historical direction and are not measurements of current Young request ranking.

Demo instructions: [MATCHING_DEMO.md](MATCHING_DEMO.md). Integration scope: [VOLUNTEER_NEARBY_INTEGRATION.md](VOLUNTEER_NEARBY_INTEGRATION.md).
