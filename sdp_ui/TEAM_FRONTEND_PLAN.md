# Frontend Work Split — Sime Darby Property Hackathon

**One product, two modules, one design system.** Use `DESIGN_SYSTEM.md` and `design-tokens.css` as the shared source of truth.

| Owner | Route | Scope | Prototype demo |
| --- | --- | --- | --- |
| You | `/community` | Events, maintenance announcements, volunteering, important township updates | Filter announcements, open event details, join a volunteer activity |
| Teammate | `/safety` | Haze, river/lake levels, temperature alerts, damaged-facility reports | View health/safety summary, submit a facility report, see its status |
| Shared | `/` | Homepage, sidebar/top bar, mobile navigation, base cards/buttons/type | Show a safety summary plus latest community news in the same page |

## Work sequence

1. Both agree on fonts, tokens, colors, card styles, navigation, and one demo township.
2. Merge the shared `AppShell`, `PageHeader`, `InfoCard`, `StatusBadge`, `AppButton` first.
3. You develop `feature/community-dashboard`; teammate develops `feature/safety-dashboard`.
4. Expose one embedded summary each: `CommunityOverview` and `SafetyOverview`.
5. Integrate both into one shared home; test mobile and desktop views together.
6. Show source labels, last-updated dates, and `Demo data` where mock readings are used.

## Your community page (priority order)

1. `All Updates` list and category filters (Events / Maintenance / Volunteer / Township Updates).
2. Event details modal with venue and time.
3. Maintenance announcement with affected place, timeline, and status.
4. Volunteer sign-up demo (local state, confirmation visible).
5. Township news updates with published-at date.

## Teammate's safety page (priority order)

1. Haze/AQI card with source, timestamp and advisory.
2. Water-level status card (demo label unless verified live data is available).
3. Temperature card with threshold-based alert.
4. Facility reports with states: Reported → In Progress → Resolved.
5. Sample facility submission flow that adds a report to the feed.
